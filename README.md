# Парсер каталога дверей

Парсер собирает модели межкомнатных и входных дверей с сайтов производителей по заданному списку линеек.

## Обрабатываемые сайты

| Производитель | Сайт |
|---|---|
| Скамбио Порте | dver.com |
| Хаусдорс | hausdoors.ru (включая aluminum.hausdoors.ru) |
| Олимп | olymp-doors.ru |
| Аэлита | aelita-doors.ru |
| Лорд | dveri-lord.ru |
| Комфорт | komfortdoors.ru |
| Двери регионов | dveriregionov.ru |
| Термодур | termo-door.ru |
| Энтро | entro-design.ru |
| АСД | as-doors.ru |

## Какие данные собираются

- Тип двери (входная / межкомнатная)
- Производитель
- Линейка
- Название модели
- Описание
- Материал (заполнен из таблицы линеек заказчика, где доступно)
- Ссылка на изображение
- Ссылка на страницу с моделью

## Какие данные НЕ собираются

- **Цены** — не собираются
- **Покрытие** — не заполняется (материал указан в поле material)
- **Фото** — не скачиваются, сохраняются только ссылки
- **Загрузка в WordPress** — не выполняется автоматически, но генерируется файл `wordpress_import.csv`

## Установка

```powershell
# Создать виртуальное окружение (если ещё нет)
python -m venv .venv

# Активировать
.\.venv\Scripts\Activate.ps1

# Установить зависимости
pip install -r requirements.txt
```

## Запуск

### Полный парсинг всех производителей

```powershell
python src/doors_parser.py --targets data/target_lines.csv --sites config/sites.yaml --out output
```

### Один производитель

```powershell
python src/doors_parser.py --targets data/target_lines.csv --sites config/sites.yaml --out output --only "Аэлита" --debug
```

### Быстрый запуск (PowerShell)

```powershell
.\run_windows.ps1
```

### Флаги

| Флаг | Описание |
|---|---|
| `--only "Название"` | Обработать одного производителя |
| `--limit-sites N` | Первые N сайтов |
| `--max-pages-per-site N` | Максимум страниц на сайт (по умолч. 200) |
| `--debug` | Подробный вывод |
| `--resume` | Дозапись (пропускает обработанные сайты) |

## Материал (material)

Материал заполнен из исходной таблицы заказчика "Линейки производителей" (поле `covering_from_source`).
Сопоставление выполнено по паре (производитель, линейка).

Если в таблице заказчика для коллекции не указан материал, поле оставлено пустым:
- **Термодур** — для всех коллекций материал не указан в исходной таблице
- **АСД** — коллекция требует ручного уточнения (см. ниже)

## АСД (as-doors.ru)

Для производителя АСД парсер собирает модели из разделов "в наличии" и "заказные".
Коллекция (target_line) заменена на "Уточнить коллекцию", так как все модели были отнесены к одной общей линейке "Все модели".
Заказчик может самостоятельно проставить коллекции для каждой модели.

## Обработка дублей и изображений

После первичного парсинга выполнена постобработка таблицы:

- Строки сгруппированы по (производитель + линейка + название модели)
- Дубли (одна и та же модель с разных страниц или с разными фото) сведены к одной записи с лучшим изображением
- Варианты вида "-- вариант N" не схлопываются — каждый остаётся отдельной строкой
- Миниатюры Tilda CDN (`/resize/20x/`) автоматически заменены на исходные изображения (`static.tildacdn.com`)
- Изображения WordPress cache/thumb с размером ≥ 400px сохранены
- Служебные изображения (логотипы, иконки, `_sale`, `qr.png`, Tilda `/empty/` и т.п.) заменены на реальные фото со страниц-источников или очищены
- Строки без хорошего фото помечены `needs_review`
- Отчёт о дублях: `output/duplicates_report.csv`
- Отчёт о заменах изображений: `output/image_audit.csv`

## Файлы результата (output/)

Результаты парсинга — в папке `output/`:

- **doors_catalog.xlsx** — основная таблица для просмотра (каталог + qa_report)
- **doors_catalog.csv** — каталог в CSV
- **wordpress_import.csv** — файл для загрузки в WordPress/WooCommerce
- **not_found.csv** — линейки, которые не удалось найти (в финальной версии пуст)
- **qa_report.csv** — отчёт качества по каждой линейке с материалом из таблицы заказчика
- **run_report.json** — технический отчёт запуска

## Статусы моделей

- **found** — модель уверенно найдена, данные корректны
- **needs_review** — есть сомнения (нет изображения, коллекция не найдена на сайте, слабое совпадение). Рекомендуется ручная проверка
- **not_found** — линейка или модель не найдена
- **error** — техническая ошибка сайта или парсинга

## Особенности парсинга

- Для сайтов **Аэлита, Lord, Hausdoors, Entro, Термодур, dver.com** модели извлекаются из галерей и изображений внутри коллекций — каждая картинка/вариант становится отдельной строкой.
- Если у модели нет отдельной карточки, `source_url` указывает на страницу коллекции.
- Для **АСД** выгружаются все модели из разделов onstock/ и zakaznyie/ по sitemap, коллекция требует ручного заполнения.
- Служебные изображения (`open.png`, `logo`, `icon`, `pixel`, `placeholder` и т.п.) отфильтрованы.
- **32 коллекции** не имеют данных на сайтах производителей — добавлены как строки-заглушки с пометкой `collection_not_found_on_site`. Заказчику нужно добавить модели для этих коллекций вручную.

## Отчёт качества (qa_report.csv)

Файл содержит статистику по каждой целевой линейке:

- material_from_table — материал из таблицы заказчика
- rows_count — сколько строк собрано
- unique_models_count — уникальных названий моделей
- image_missing_count — строк без изображения
- status — общий статус линейки (found / not_found / needs_manual_review)
- comment — причина, если требуется внимание

Линейки со статусом `needs_manual_review` рекомендуется проверить вручную.
